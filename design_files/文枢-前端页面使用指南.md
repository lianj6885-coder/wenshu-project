# 文枢前端页面使用指南

> 适用版本：Python 控制平面 + pi Agent 执行引擎版  
> 默认访问地址：<http://localhost:8080>

## 1. 页面角色与演示账号

文枢会根据登录账号自动进入不同工作台，不需要手动选择身份。

| 角色 | 演示账号 | 默认密码 | 工作台能力 |
|---|---|---|---|
| 学生用户 | `student` | `student123` | 制度问答、引用查看、历史会话、反馈、个人长期记忆 |
| 部门管理员 | `jwc_admin` | `admin123` | 本部门文档、审核、反馈、Trace、Skill、记忆和 Agent 状态 |
| 超级管理员 | `admin` | `admin123` | 全局部门、Loop、策略、实验、记忆、审核和 Agent 网络 |

本地演示还提供财务处管理员 `cwc_admin / admin123`。

## 2. 登录与退出

### 2.1 登录

1. 打开 <http://localhost:8080>。
2. 输入账号和密码；本地演示时也可点击身份卡片自动填入。
3. 点击“安全登录”。
4. 系统依据 Token 中的角色和部门范围进入相应工作台。

### 2.2 退出

- 学生端：点击左下角用户区域右侧的退出图标。
- 管理端：点击左侧导航底部“退出系统”。

退出会清除浏览器登录 Token，不会删除会话、文档或记忆。

## 3. 学生制度问答工作台

### 3.1 发起可信问答

1. 登录学生账号。
2. 点击示例问题，或在底部输入问题。
3. 按 Enter 或点击发送；Shift + Enter 换行。
4. 系统依次完成意图识别、部门路由、active 制度检索、pi Agent 生成与 Verifier 校验。
5. 回答卡片展示检索证据数、意图、回答置信度和校验分数。

### 3.2 查看制度引用

1. 点击回答底部“查看 N 条制度依据”。
2. 查看文档标题、章节路径或切片编号，以及支撑回答的原文。
3. 制度中没有明确答案时，系统应明确提示未找到规定，不能自行编造。

### 3.3 查看部门路由

回答卡片的“智能路由”显示命中部门和主要理由。跨部门问题可能同时命中多个部门。

### 3.4 提交反馈

- “有帮助”：写入采纳信号。
- “复制”：复制答案，同时形成复制使用信号。
- “需改进”：写入负反馈，供 Observe 和 Reflect 分析。

继续追问或在未评价时离开，还会形成追问或会话中断等隐式信号。反馈不会直接修改制度事实，而是进入受治理的 Loop。

### 3.5 管理历史会话

1. 左侧“最近会话”显示本人历史。
2. 点击标题恢复消息和引用。
3. 点击“开启新会话”创建独立上下文。
4. 鼠标移到历史项后点击删除图标，可删除本人会话及关联情景记忆。

用户不能读取或删除其他人的会话。

### 3.6 使用个人长期记忆

1. 点击“我的长期记忆”。
2. 填写偏好名称，例如 `answer_style`。
3. 填写偏好内容，例如“简洁、分点回答”。
4. 点击“记住这个偏好”。
5. 后续问答会选择性召回该偏好。
6. 不再需要时点击删除图标。

长期记忆必须由用户明确同意。身份证、密码、联系方式等敏感信息会被后端拒绝。

## 4. 部门管理员工作台

部门管理员只能查看和操作绑定部门的数据。例如 `jwc_admin` 只能访问 `dept_jwc`。

### 4.1 态势总览

1. 点击“态势总览”。
2. 查看本部门文档、Chunk、Skill、冲突、Trace、审核单和题库规模。
3. 查看人在环中、人在环上或人在环外阶段。
4. 根据正确率和样本进度判断距离渐进退出的差距。

部门阶段由真实审核质量自动推进，不能手工跳级。

### 4.2 上传部门文档

1. 点击“知识资产”。
2. 确认本部门，点击“选择制度文件”。
3. 选择 PDF、DOCX、Markdown、TXT 或 HTML。
4. 等待状态从 `queued` 进入 `running`，再变为 `completed`。
5. 页面展示上传、解析、清洗、切片、元数据、向量化、索引和关系发现 Pipeline。
6. 入库完成后系统自动生成审核单。

### 4.3 文档状态治理

- 可归档当前制度，或将归档/草稿恢复为 active。
- 可查看版本、切片数、向量状态和 Pipeline。
- 只有 `active` 文档参与学生检索；旧版本应归档。

### 4.4 可信审核

1. 点击“可信审核”，选择“待审核”。
2. 点击审核单“查看详情”。
3. 每题逐项选择“正确”或“错误”。
4. 错误题填写纠正意见。
5. 所有题处理完后提交；未选择的题不会默认通过。
6. 结果写入题库与反馈，并累计部门正确率。

### 4.5 查看部门 Loop

1. 点击“进化 Loop”。
2. 查看 Execute → Observe → Reflect → Adapt → Deploy。
3. 加载待处理反馈和最近 Trace。
4. 查看本部门 Skill、Hooks、Rules 的状态和指标。

部门管理员不能触发全局 Loop 或切换全局阶段；页面不显示相应操作，后端也拒绝越权请求。

### 4.6 查看部门记忆与实验

“记忆与实验”展示工作记忆、情景记忆、组织知识记忆、程序性学习记忆、独立事实平面及本部门策略实验。部门视角不展示用户长期记忆隐私。

### 4.7 查看部门 Agent 网络

“Agent 网络”展示 Orchestrator、Intent、Retrieval、Answer、Verifier 执行链，以及模型、温度、副本、文档、Skill、Hook、审核质量和热点。

## 5. 超级管理员工作台

### 5.1 全局态势总览

1. 点击“态势总览”。
2. 查看全系统部门、Trace、审核单、题库、Skill 和采纳率。
3. 逐部门比较文档、冲突、正确率和 Human Fade-out 阶段。

### 5.2 创建部门

1. 点击“知识资产”。
2. 填写唯一 ID、部门名称和分类。
3. 点击“创建”。新部门会出现在总览和 Agent 网络。

部门管理员看不到该操作。

### 5.3 全局文档与审核

- 文档页可按部门查看制度资产。
- 审核中心可按部门和状态过滤。
- 超级管理员可处理任意部门审核单，但业务事实判断建议由部门管理员完成。

### 5.4 手动触发 Loop

1. 点击“进化 Loop”。
2. 先加载反馈和 Trace，确认有待处理信号。
3. 点击“触发新一轮 Loop”。
4. 作业进入 Redis Stream，页面自动轮询，不需要手工刷新。
5. 五阶段时间线会依次显示 Execute、Observe、Reflect、Adapt、Deploy 的完成或运行状态。
6. 完成后查看结构化报告：反馈数、bad case、根因分布、策略候选、发布数量、资产前后变化与下一步建议。
7. “最近 Loop 运行记录”可重新打开历史报告，不再只显示 `job_id`。

不要在没有反馈样本时反复触发 Loop。

### 5.5 切换全局 Loop 阶段

- 人在环中：自动产物必须审核。
- 人在环上：高置信度自动生效，低置信度进入审核。
- 人在环外：圈定范围自动运行，人负责边界和监督。

全局阶段控制策略自动生效阈值，不会强行跳过各部门审核条件。

### 5.6 Skill 审核与生命周期

1. 初始页面自带三条真实可执行的基线 Skill，用于演示极端天气、事项步骤和学术截止日期工作流。
2. 展开 Skill 卡片查看触发词、执行步骤、灰度比例、次数、成功率、版本、来源和状态。
3. 在学生端提出命中触发词的问题后，基线 Skill 会真实改变检索 query、top_k 和回答模板，并累计命中/成功指标。
4. Loop 自动挖掘出的 pending Skill 可点击“审核通过”。
5. 查看独特规则和 badcase 反思出的 rubric 规则。
6. 在“记忆与实验”查看策略快照、灰度分桶、生命周期建议和回滚。

### 5.7 阅读记忆与实验全景

1. 五个记忆平面显示数量、用途和存储介质。
2. 事实平面显示 active 文档、Chunk、关系和冲突。
3. 记忆治理显示使用记录、失效知识和待确认候选。
4. 策略演进显示版本、执行、实验和生命周期建议。
5. 灰度流量显示 treatment/control 分桶。
6. 反馈信号雷达汇总采纳、点踩、纠错、复制、追问、中断和 Verifier 信号。
7. 最近 Trace 显示可追溯结果与时延。

### 5.8 Agent 网络与弹性

比较各部门执行单元、模型、文档、Skill、Hook、审核质量和热点。页面中的 1–20 是目标弹性范围；本地 Compose 通常只有一个实例，真实扩缩容需要 Kubernetes/HPA。

## 6. 核心概念

### 6.1 Loop

Loop 不是模型自行改代码，而是受治理的策略闭环：Execute 保存 Trace；Observe 收集信号；Reflect 分析根因；Adapt 生成策略候选；Deploy 经审核、回放和灰度后生效，失败可回滚。

### 6.2 Skill

Skill 是针对重复问题模式的可执行工作流，不只是一句提示。重点查看触发词、工作流、版本、成功率、实验和生命周期。

### 6.3 五个记忆平面与事实平面

| 平面 | 页面含义 | 是否作为制度事实 |
|---|---|---|
| 工作记忆 | 当前会话上下文，短期 TTL | 否 |
| 情景记忆 | 历史事件和会话摘要 | 否 |
| 用户语义记忆 | 用户明确同意的稳定偏好 | 否 |
| 组织知识记忆 | 带来源、版本和审核的 FAQ/提示 | 必须回查来源 |
| 程序性学习记忆 | Skills、Hooks、Rules 和实验 | 否 |
| 独立事实平面 | active 文档、完整 Chunk 和关系 | 是 |

记忆用于理解与引导，关键结论必须回到事实平面并附引用。

## 7. 常见问题

### 页面显示后端不可用

```bash
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
docker compose ps
docker compose logs --tail=100 backend web
```

### 文档长时间停留 queued 或 running

```bash
docker compose logs -f worker
```

复杂文档还会执行向量化、冲突检测和审核题生成，首次处理可能需要几十秒。

### 部门管理员为何看不到新建部门或手动 Loop

这是权限设计。部门管理员只能治理本部门；全局组织和策略操作属于超级管理员。

### 如何安全停止系统

```bash
docker compose down
```

不要随意执行 `docker compose down -v`，它会删除 MongoDB、Redis 和上传文件数据卷。
